# 测试与验证原则

## 目标：MVP 加合理增量

测试用于证明核心行为和重要失败路径可靠。测试数量和覆盖率不作为目标。

1. 先保证最小可用流程与关键生命周期，再按新增行为、具体未覆盖风险或实际缺陷补充测试。
2. 新用例应能说清会捕获什么失败；已有用例能表达该约束时，优先复用或扩展。
3. 不为简单字段赋值、平凡封装、内部调用顺序或与实现同构的细节增加测试。
4. 同一行为默认在最合适的一层验证；只有不同层确有独立契约时才分别测试。
5. 修复缺陷时优先建立可暴露问题的回归验证；已有测试能稳定复现时，不再复制一个同类用例。
6. 跨平台构建、实际运行、测试代理和真实代理各自提供不同证据，不能互相替代。

## MVP 行为基线

| 需要证明的行为 | 当前主要验证位置 |
| --- | --- |
| 直接连接与 HTTP CONNECT 下的反向映射、双向数据、并发配对和关闭 | `internal/server/server_test.go` |
| 错误身份与服务配置拒绝、重连、取消、配对超时、连接上限和一次性请求 | `internal/server/server_test.go` |
| CONNECT 认证、握手取消、响应后的缓冲数据和有界响应 | `internal/dial/dial_test.go` |
| 控制帧长度、版本、截断与载荷边界 | `internal/wire/wire_test.go` |
| 示例配置可解析，未知字段被拒绝 | `internal/config/config_test.go` |

本表描述本地基线，实际已执行范围见 [验证记录](../../VALIDATION.md)。真实代理与目标系统验证按 [演进规划](../../ROADMAP.md) 推进。

## 编写方式

- 优先使用真实回环 socket、临时目录与标准库，不为简单场景引入 mock 框架或额外测试依赖。
- 使用动态端口、显式同步和有界等待，避免固定端口、盲目 sleep 和无限等待。
- 清理连接、监听器和 goroutine，测试失败时也应能结束；不能依赖测试进程退出代替清理。
- 断言用户可见行为或重要边界，避免绑定私有字段布局与内部调用次数。为故障注入访问内部状态时，结论仍应落在外部行为上。
- 只在负载或时序本身是被测问题时增加压力与重复次数；性能耗时阈值不随意进入普通正确性测试。

## 按影响选择检查

| 改动 | 基本检查 |
| --- | --- |
| 文档、规则、文档链接 | 检查引用、内容分工与事实一致性；无需重跑 Go 测试 |
| 配置或命令行行为 | 对应包的行为测试及相关配置检查 |
| 转发、协议、并发、连接所有权 | `gofmt`、`go test ./...`、`go test -race ./...`、`go vet ./...` |
| 平台相关行为或构建方式 | 受影响目标的构建；涉及运行语义时补相应系统的实际运行 |
| 性能优化 | 受影响行为的正确性验证，加相同条件的前后基准对照 |

相关检查通过后，只有新改动、失败或未解决的问题才扩大或重复检查。CI 的全量检查可以继续提供统一基线，不要求本地对每次文档编辑重跑它。

## 记录结果

报告运行环境、检查内容和结果，并明确未执行的验证。不能将“CI 文件已配置”写成“CI 已通过”，也不能将“交叉构建通过”写成“目标系统运行通过”。

资源开销必须记录测量条件。没有约定预算或测量结果时，不宣称内存、CPU、吞吐或延迟指标已经达标。
