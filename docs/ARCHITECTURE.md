# 当前架构与工程取舍

本文件描述已经采用的实现，后续目标见 [项目演进规划](../ROADMAP.md)。规则分别由 [代码规范](rules/CODING.md) 和 [测试原则](rules/TESTING.md) 维护。

## 职责边界

sertun 提供 TCP 反向映射，负责注册服务、请求回连、配对连接和双向转发。AnyTLS/HY2 等外层代理独立运行，提供传输与加密。

客户端通过 HTTP CONNECT 或直接连接访问 sertun 服务端。代理模式中的服务端地址从代理出口访问；直接连接模式中的地址从客户端访问。配置代理后不自动回退为直接连接。

## 连接流程

1. 服务端按配置监听隧道接入口和映射端口。
2. 客户端建立控制连接，以客户端 ID、token 和服务列表注册。
3. 服务端校验配置，为本次控制会话分配标识；同一客户端 ID 只允许一个在线会话。
4. 访问者连接映射端口后，服务端分配一次性请求标识，通过控制连接通知客户端。
5. 客户端连接本地服务，再建立独立业务回连，携带客户端、会话和请求标识。
6. 服务端配对后，业务连接直接双向转发原始字节。

控制消息采用有长度上限的 JSON 帧；业务数据不叠加自定义持续分帧。

macOS 的原生 TCP 对使用可复用的分级缓冲：每个方向先用 32 KiB，累计传输 1 MiB 后切到 256 KiB，减少大流量下的读写调用。切换不等待填满缓冲、不增加业务分帧；半关闭与取消仍由 relay 管理。其他连接实现保留自身的复制方法，其他系统由标准库选择原有的高效复制路径。

## 生命周期与失败行为

- 服务端配置允许暴露的服务与监听地址；客户端配置同名服务的本地目标，注册列表需完全匹配。
- 控制会话取消时，该会话的待配对请求和业务连接一并结束。重新注册后可以建立新连接，已断 TCP 会话不恢复。
- 配对超时、身份不符、过期或已使用的请求会被拒绝。
- 握手、待配对请求和业务连接各有上限；客户端离线或达到上限时关闭对应的访问连接。
- 本地 TCP 转发支持半关闭，最终语义取决于外层代理；实际兼容范围由验证证据说明。

这些是当前行为契约；修改时按工作流程更新相关说明与必要测试。

## 当前工程选择

以下选择已经落在代码中，不代表用户逐项确认，也不约束后续在证据充分时调整。

| 选择 | 理由 | 代价或重新评估的条件 |
| --- | --- | --- |
| 单一可执行文件、两个角色 | 构建与分发简单 | 不引入后台管理框架 |
| 标准库为主，仅使用 TOML 第三方运行依赖 | 控制依赖与维护成本 | 新依赖需有具体收益 |
| 服务端静态授权映射 | 端口权限明确，注册协议简单 | 调整服务需要修改配置并重启 |
| 每条业务使用独立连接 | 复用外层提供的连接或流能力 | 新连接建立成本需要测量 |
| 暂不增加工具自身的多路复用 | 减少额外分帧、缓冲和流控 | 确有连接约束或瓶颈时重新评估 |
| 控制协议与原始数据转发分离 | 业务转发路径保持直接 | 连接配对与关闭必须有明确所有权 |

协议或配置兼容性改变时，说明受影响行为、版本处理和迁移方式；不提前实现尚无需求的兼容层。

## 性能验证工具

benchmark 通过独立生产二进制比较 sertun 与固定版本的 frp，按需启动隔离的 Mihomo 实例。所有负载串行执行，失败中止，临时进程与配置在退出时回收；原始结果与汇总一起保存。方法和复现入口见 [benchmark 说明](../bench/README.md)。该工具没有增加产品依赖，也不修改已有转发行为。

优化对照可用 `-baseline-ref` 从 Git 提交导出源码，以同一 Go 编译器和构建参数重建优化前版本，并与当前工作区版本交错测量。报告同时给出 CPU 百分比和每 GiB 有效回显数据的 CPU 时间成本，避免只比较不同吞吐下的 CPU 百分比。
