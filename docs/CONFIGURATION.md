# 配置与运行行为

完整示例：[服务端](../examples/server.toml)、[客户端](../examples/client.toml)。配置采用 TOML，未知字段会报错。

## 映射与身份

服务端每个 `[[clients]]` 定义客户端 ID 与 token，嵌套的 `[[clients.services]]` 定义允许暴露的服务名称与监听地址。客户端的 `[[services]]` 定义同名服务的本地目标。

两端服务列表必须完全一致；同一客户端 ID 只允许一个在线控制会话。token 可用 `sertun token` 生成，认证信息和载荷的传输保护由外层代理或可信网络承担。

客户端 `proxy` 仅接受普通 HTTP CONNECT 代理，支持 URL 中的 Basic 认证；当前不支持 HTTPS 代理入口或 SOCKS5。使用代理时 `server` 从代理出口访问，直连时从客户端访问。

## 默认值

以下配置可省略：

| 位置 | 配置项 | 默认值 | 用途 |
| --- | --- | --- | --- |
| 服务端 | `listen` | `127.0.0.1:7000` | 隧道接入口 |
| 两端 | `timeout` | `"10s"` | 连接与握手超时；服务端等待业务回连超时 |
| 两端 | `heartbeat_timeout` | `"60s"` | 控制连接无消息超时 |
| 服务端 | `max_handshakes` | `64` | 隧道接入握手并发上限 |
| 服务端的每个客户端 | `max_connections` | `128` | 等待与转发中的业务连接总上限 |
| 服务端的每个客户端 | `max_pending` | `32`，不超过连接上限 | 待配对连接上限 |
| 客户端 | `proxy` | 空 | HTTP CONNECT 代理，空值表示直连 |
| 客户端 | `max_connections` | `128` | 本地业务连接上限 |
| 客户端 | `heartbeat_interval` | `"20s"` | 保活间隔 |
| 客户端 | `reconnect_min` | `"1s"` | 重连初始基础退避 |
| 客户端 | `reconnect_max` | `"30s"` | 重连最大基础退避 |

心跳超时应大于保活间隔并留出余量。重连带少量随机扰动。认证错误和服务列表不匹配会退出；网络故障和暂时存在的重复会话会自动重试。

## 连接生命周期

客户端离线、连接超过上限或配对失败时，服务端关闭对应访问连接。控制会话中断时，相关业务连接结束；重新注册可建立新连接，已断开的 TCP 会话不恢复。

当前业务结束后关闭回连，不存在可配置的空闲复用池。60 秒空闲通道复用属于 [后续规划](../ROADMAP.md)，当前配置不要加入相关字段。

转发支持本地 TCP 半关闭；外层代理是否保留该语义需要独立验证。测试范围见 [验证记录](../VALIDATION.md)。

## 配置检查

```sh
sertun server -c server.toml -check
sertun client -c client.toml -check
```

命令只校验配置，不监听端口，也不检查代理、远端或本地服务是否可达。使用方式见 [README](../README.md)。
