# 配置与运行行为

示例见 [服务端](../examples/server.toml) 和 [客户端](../examples/client.toml)。配置是 TOML，写错字段名会直接报错，不会静默忽略。

## 映射与身份

服务端每个 `[[clients]]` 定义一个客户端 ID、token 和它允许暴露的服务；嵌套的 `[[clients.services]]` 写服务名和监听地址。客户端的 `[[services]]` 写同名服务对应的本地地址。

两端服务列表必须一致。同一个客户端 ID 只允许一个在线控制会话。token 用 `sertun token` 生成。token 和业务数据本身不加密，传输保护由外层代理或可信网络负责。

客户端 `proxy` 只接受普通 HTTP CONNECT 代理，URL 里可以带 Basic 认证。不支持 HTTPS 代理入口或 SOCKS5。走代理时 `server` 从代理出口访问，直连时从客户端访问。

## 默认值

下面这些可以省略：

| 位置 | 配置项 | 默认值 | 用途 |
| --- | --- | --- | --- |
| 服务端 | `listen` | `127.0.0.1:7000` | 隧道接入口 |
| 两端 | `timeout` | `"10s"` | 连接与握手超时；服务端等待业务回连超时 |
| 两端 | `heartbeat_timeout` | `"60s"` | 控制连接无消息超时 |
| 服务端 | `max_handshakes` | `64` | 隧道接入握手并发上限 |
| 服务端的每个客户端 | `max_connections` | `128` | 等待与转发中的业务连接总上限 |
| 服务端的每个客户端 | `max_pending` | `32`，不超过连接上限 | 待配对连接上限 |
| 客户端 | `proxy` | 空 | HTTP CONNECT 代理，空值表示直连 |
| 客户端 | `max_connections` | `128` | 本地业务连接上限 |
| 客户端 | `heartbeat_interval` | `"20s"` | 保活间隔 |
| 客户端 | `reconnect_min` | `"1s"` | 重连初始基础退避 |
| 客户端 | `reconnect_max` | `"30s"` | 重连最大基础退避 |

心跳超时要大于保活间隔，并留出余量。重连时间带一点随机抖动。认证失败和服务列表不匹配会直接退出；网络故障和暂时重复的会话会自动重试。

## 连接生命周期

客户端离线、连接超过上限或配对失败时，服务端关闭对应的访问连接。控制会话中断后，相关业务连接跟着结束。重新注册可以接新连接，已经断开的 TCP 会话不会恢复。

业务结束后回连就关了，没有可配置的空闲复用池。60 秒空闲通道复用属于[后续规划](../ROADMAP.md)，现在的配置里不要加相关字段。

本地 TCP 转发支持半关闭。外层代理是不是保留这个语义，要单独验证。测试范围见[验证记录](../VALIDATION.md)。

## 配置检查

```sh
sertun server -c server.toml -check
sertun client -c client.toml -check
```

这两条只校验配置，不监听端口，也不检查代理、远端或本地服务通不通。使用方式见 [README](../README.md)。
